# Что уже проверено и что нужно владельцу

Приложение работает локально с настоящими данными и semantic retrieval. Полная генерация и живой пешеходный routing считаются подтверждёнными только после успешного ответа соответствующего провайдера.

## 1. Подключить Gemini

Откройте уже подготовленный `.env` в корне и задайте `GEMINI_API_KEY`. Копировать файл поверх существующего не нужно. Значение не нужно отправлять в чат, указывать в командной строке или записывать в frontend. `LLM_MODEL` задаёт модель.

Ключ создаётся в [Google AI Studio](https://aistudio.google.com/apikey); требуется аккаунт Google. Официальная инструкция: [Gemini API keys](https://ai.google.dev/gemini-api/docs/api-key).

Из корня Windows:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_live_readiness --providers gemini --require-all
```

Linux/macOS:

```sh
.venv/bin/python -m scripts.check_live_readiness --providers gemini --require-all
```

Команда загружает локальный semantic индекс, выполняет настоящий RAG-запрос на публичной POI, проверяет `mode=rag` и grounding. Погода и routing изолированно отключены, чтобы не смешивать причины ошибок и не расходовать дополнительные запросы. Запуск может потреблять квоту Gemini: максимум две генерации и две отдельные проверки модели, общий лимит генератора 25 секунд.

Текст объяснения использует проверяемые слоты фактов; backend подставляет источник, вычисления и оценки, затем отдельный модельный reviewer проверяет утверждения и идеи. Такая проверка вероятностна и не доказывает отсутствие всех ошибок. При отказе reviewer/валидации включается маркированный шаблонный ответ.

Без ключа результат **skipped**, а не «успешно». При ключе, но ошибке/невалидной генерации — **failed**. `docs/live-readiness.json` хранит только статус, модель, публичные ID, checksum и длительность. Ключи, промпты, заголовки и исходные provider ответы не сохраняются.

После успешной проверки перезапустите приложение, чтобы оно прочитало обновлённое окружение. В интерфейсе реальный запрос должен показать режим RAG.

## 2. При необходимости подключить пешие маршруты

Задайте серверный `ORS_API_KEY`, затем:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_live_readiness --providers ors --require-all
```

Это один настоящий запрос `foot-walking` туда и обратно между двумя публичными точками из snapshot. Проверяются положительная длина/время, обратный участок и GeoJSON. Без ключа маршрут не придумывается, остаётся прямое расстояние с предупреждением.

Проверка обоих провайдеров: `python -m scripts.check_live_readiness --require-all` (используйте Python из `.venv`). Успешный ORS smoke не доказывает доступность всех маршрутов, входов и путей для коляски.

## 3. Проверить пользу с человеком

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_conversations
```

Сервер должен работать на `http://127.0.0.1:8000`. Команда отправляет 17 настоящих разговорных запросов из brief, использует реальные POI и сохраняет ответы и объективные проверки в `tests/benchmark/conversation-results.json`. Включены два ночных запроса: без даты/времени ожидается уточнение, с явно заданным временем Астаны проверяются предупреждения и отсутствие выдуманных часов.

**Объективные проверки:** найденные ID принадлежат датасету, обязательные свойства подтверждены, запреты соблюдены, unknown не объявляется open, прямая дистанция не выдаётся за время пути, бюджет не расширяется, рискованные запросы уточняются.

**Пользовательская релевантность:** отдельная ручная оценка в `tests/benchmark/human-review.csv`. Автоматический pass не означает, что человеку понравился вариант. Файл не перезаписывается повторным запуском, чтобы сохранить работу рецензента.

Шкала для каждого из трёх критериев:

- 0 — запрос не решён / сведения не помогают / объяснение ошибочно.
- 1 — частично полезно, есть существенный пробел.
- 2 — конкретно, понятно и подходит поставленному запросу в пределах известных данных.

Критерии: релевантность, опора на данные, возможность принять решение. Нужны имя/роль рецензента и короткая причина оценки. Модель не ставит баллы собственным ответам.

## 4. Публикация

Для публичного URL нужен аккаунт хостинга/VM и домен, если он требуется. Инструкция: `docs/deployment.md`. Docker требует работающий Engine; наличие CLI не считается выполненным запуском контейнера.

Для YouTube уже готов [MP4 с русской озвучкой](../demo/QADAM-demo-narrated.mp4) длительностью 2:30 и [SRT-субтитры](../demo/QADAM-ru.srt). Голос синтетический, Microsoft Irina Desktop; создан локально. Владелец смотрит видео, загружает MP4, добавляет описание из `demo/script.md` и выбирает «Доступ по ссылке». До реальной загрузки публичного URL нет. Исходная запись без звука сохранена как `demo/QADAM-demo.webm`.

Сами ключи и учётные данные проекту в Git не передаются.
