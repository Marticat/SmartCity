## Frozen benchmark

Запуск: `python -m scripts.benchmark`. Файл `tests/benchmark/frozen.json` сохранён до измерения; 12 запросов по конкретному названию и 3 случая строгих ограничений. QA разметил relevant ID по настоящему snapshot, все другие ID для именованного запроса считаются нерелевантными. Developer smoke-примеры отдельно в `developer-tuning.json`, не входят в оценку.

После независимого аудита исправлена нормализация `internet_access=yes`: наличие интернета не подтверждает Wi-Fi. Изменились 6 значений и checksum датасета; число и идентичности POI прежние. В frozen файле обновлена только metadata checksum, тексты запросов и все метки сохранены. Исходные результаты лежат в `results-initial.json`; итоговая оценка повторена на исправленных данных.

- Hit@3 по именованным запросам: **11/12 (91.7%)**.
- Precision@3 по тем же 12: **0.3056**. На запрос размечен один целевой ID, поэтому теоретический максимум этой метрики здесь 1/3.
- Нарушения размеченных категориальных/обязательных условий: **0/15 запросов**.
- «Кофе с обязательной розеткой»: ожидаемо пустой результат.
- Неуспех: запрос «Парк Пушкинский, не кафе» не вывел целевой ID в top-3. Метки после измерения не исправлялись ради улучшения цифры.

Это маленькая проверка нахождения заданных мест и ограничений, не репрезентативная оценка общего разговорного подбора. Нужна независимая человеческая разметка широких сценариев. Метод и каждый результат: `tests/benchmark/results.json`. Модель сама себя не оценивала.

## Задержки

Отдельный процесс Store + загрузка E5: **10 633.76 мс**. Это cold process startup на данной машине с уже скачанной моделью, не гарантированное время на другой системе. Первое измерение до прогрева файлового кэша было 47 369 мс; исходный результат сохранён.

15 последовательных retrieval запусков: медиана **38.32 мс**, максимум **533.12 мс**; включает фильтры, semantic encoding, FTS5 и fusion, без внешних провайдеров. Первый encoding входит в выборку.

`python -m scripts.measure_api`: **10 реальных HTTP запросов** к уже запущенному серверу. Первый **548.31 мс**, оставшиеся 9: медиана **41.34 мс**, максимум **58.46 мс**. Режим `search_only`, semantic готов, Open-Meteo `available` с последующим кэшем. Это полный API ответ **без LLM**, не скорость RAG-генерации. Публичный anchor — Ботанический сад; личная позиция не использовалась. Детали: `tests/benchmark/api-latency.json`.

## Что остаётся открытым

- Настоящий Gemini end-to-end: добавить `GEMINI_API_KEY` в `.env`, перезапустить сервер, выполнить запрос и убедиться в `mode=rag`. Текущая модель по конфигурации `gemini-3.8-flash`; провайдер и schema adapter реализованы, live ответ не проверен.
- Настоящий пешеходный ORS маршрут: требуется `ORS_API_KEY`; порядок координат, foot-walking, возвращение и ошибки проверены fixtures. Геометрия маршрута в UI не выдаётся за готовый маршрут.
- Docker image/run: нужен запущенный Docker Engine. Конфигурация разобрана, native путь работает.
- CI workflow создан, но GitHub Actions в удалённом репозитории не запускался.
- Поддерживается консервативный subset opening_hours, сложные правила дают unknown. Полноценного общего OSM-парсера нет.
- Пользовательская оценка «решение за полминуты», широкая conversational relevance и трёхъязычность не измерены.
- Публичный хостинг и YouTube не опубликованы; отсутствует авторизованный аккаунт.

## Повтор браузерной проверки

После запуска сервера:

```sh
npm --prefix frontend ci
cd frontend
npx playwright install chromium
cd ..
node scripts/verify-browser.cjs
node scripts/verify-resilience.cjs
```

Для CI / изолированного Linux может потребоваться `npx --prefix frontend playwright install --with-deps chromium`. Автотесты не требуют внешних API ключей. Сценарий видео — `demo/script.md`, запись — `node demo/record.cjs`.
