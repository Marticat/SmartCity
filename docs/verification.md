## Независимые разговорные сценарии

`python -m scripts.evaluate_conversations` отправляет **17 настоящих запросов** заранее сохранённых в `tests/benchmark/conversations.json`. Сценарии покрывают прогулку с кофе, два часа работы, обязательные и необязательные удобства, семью внутри помещения, историю, интерактивный музей, отрицание кафе, возврат, доступность, бесплатность, вылет, закрытую крышу, другую географию и два ночных визита.

Первый запуск дал **16/17**: фраза «Wi-Fi не обязателен» ошибочно включала обязательное условие. Результат сохранён в `conversation-results-initial.json`. Исправлен production parser и добавлены регрессионные тесты; тексты и ожидания evaluator не изменялись. Повтор на той же версии данных дал **17/17 объективных проверок**, медиана 50.36 мс. Полные фактические ответы, checksum набора и файла сценариев находятся в `conversation-results.json`.

Evaluator не импортирует production parser/filter. Он независимо проверяет реальные ID и исходные поля, обязательные атрибуты, запрещённые категории, расстояние по формуле сферы, отсутствие выдуманного времени пути/часов, бюджет и необходимые уточнения. Его собственные тесты подают ошибочные ответы и проверяют обнаружение дефектов.

**Это не оценка пользовательской полезности.** Таблица `tests/benchmark/human-review.csv` оставлена без баллов: человек оценивает релевантность, опору на данные и возможность принять решение по шкале 0–2. Повтор команды не стирает оценки рецензента. Генератор не оценивает себя.

Наблюдения QA по реальным ответам, без присвоения человеческого балла:

- Смешанный запрос «прогуляться, потом кофе» возвращает кафе. Полный последовательный маршрут из двух занятий не построен.
- Для семьи внутри помещения найдены OSM playground с подтверждённым indoor, но без собственных названий. Это слабо помогает выбрать вход без полевой проверки.
- Интерактивный музей первым связан с официальным описанием Национального музея. Другие места без интерактивности не получают обещания этого свойства.
- Ночной запрос с датой не обещает освещение и безопасность; часы ряда мест неизвестны.

## Живые провайдеры и оставшиеся шаги

`python -m scripts.check_live_readiness` фактически выполнен. Оба провайдера получили `skipped / missing_server_variable`, а не pass. Receipt — `docs/live-readiness.json`. При добавленном ключе тот же CLI делает настоящий вызов: Gemini должен вернуть `mode=rag`, ORS — пешеходный путь с возвратом. Секреты и raw provider ответы не записываются; для обязательной проверки используется `--require-all`.

Генерация со слотами фактов, evidence и отдельным reviewer проверена mock provider тестами. Дополнительно настоящий установленный Gemini SDK сериализовал обе Pydantic-схемы и обработал ответы через offline `httpx.MockTransport`. Это не заменяет live вызов. Reviewer вероятностный; удачный ответ не является гарантией отсутствия галлюцинаций. Общий предел — 25 секунд и максимум 4 обращения к модели.

Другие открытые пункты: независимая пользовательская оценка, полевые входы/услуги, сложные OSM opening_hours, полный многошаговый маршрут, production Docker запуск и удалённый CI, публичный URL и YouTube. Русский — основной язык, полноценная трёхъязычность не заявлена. Точные действия владельца: `docs/readiness.md`.

## Повтор браузерной проверки

После запуска сервера:

```sh
npm --prefix frontend ci
cd frontend
npx playwright install chromium
cd ..
node scripts/verify-browser.cjs
node scripts/verify-resilience.cjs
node scripts/verify-context.cjs
```

Для Linux CI: `npx --prefix frontend playwright install --with-deps chromium`. Браузерные проверки не требуют API ключей. 17 разговорных запросов следует запускать отдельно от других циклов: backend ограничивает частоту до 30 запросов в минуту. Сценарий видео — `demo/script.md`.
